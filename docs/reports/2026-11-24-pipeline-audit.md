# 数采、训练与评测审查（2026-11-24）

[返回项目进展](../experiments.md) · [夹爪控制版本](../../simulation/gripper-control.md)

**结论：发现了需要修复的评测版本衔接与结果复用问题；当前新版 28 场失败没有证据表明是“夹得很好，却被时间或 5 N 门槛判掉”。** 不能因此承诺整个评测器已经没有问题。

本轮阅读生产脚本，逐文件检查已入库 968 条 HDF5 的时间/动作/监督元数据，复核 A40 的旧版、新版各 28 场原始诊断与物理轨迹，并对 3 次抬升预检拒绝做离线几何复算。没有重训、没有重跑模型闭环、没有运行冻结 80 任务。未重复读取所有 RGB 像素或重算全库大文件哈希；文件内容哈希沿用入库回执。

**部署状态：下述修复已通过本地测试和服务器独立暂存目录验证，并随本次 GitHub 代码同步发布；尚未覆盖生产根目录。** 正在运行的采集总控不受仓库同步影响，仍须在后续安全切换时部署补丁并重新预检。所有已发表成绩维持原值。

## 2. 安全预检的保守性：确实存在，但不能直接换算成成功率

对旧 A40 开发日志中的三次 `lift_path_rejected`，使用各自真实触发时的关节、手腕和夹爪位置，重算同一条 8 cm 抬升路径：

| 场景 | 实测开口 | 双指垫力 | 2 mm 裕度 | 0.2 mm 裕度 | 0 裕度 |
|---|---:|---|---|---|---|
| B_9828 | 1.238 mm | 空 | 两指几何距离不足 | 通过 | 通过 |
| B_9832 | 1.293 mm | 空 | 两指几何距离不足 | 通过 | 通过 |
| C_9817 | 1.581 mm | 空 | 两指几何距离不足 | 通过 | 通过 |

这三例说明：**日志里的“自碰风险”是 2 mm 安全距离不足，不是已经证明发生了网格穿透，更不是已经证明 PhysX 发生真实碰撞。** 几何预检使用近似碰撞形状；零裕度通过也不等于完整物理抬升已经通过。

但是这三次触发均为空夹：没有双指垫目标接触、抬升实际执行 0 步。即使允许抬手，也不能据此把它们改记成功。新版 `adaptive` 已不允许仅凭空夹触底触发试提。

剩余工作是给“真实相交 / 仅安全裕度不足 / IK 不可达”分别记录原因，再用确实夹住薄件的专家回放校准指间裕度。**本轮没有把所有碰撞裕度清零，也没有给指爪相互碰撞加通用白名单。** 参考：[抬升预检](../../simulation/isaac_snapshot/vertical_lift.py)、[碰撞模型](../../simulation/isaac_snapshot/school_planner.py)。

## 3. 当前 28 场失败是否被测试规则误杀

本节重新读取的是已完成的修复版 A40 评测，不是新跑出的成绩。

| 指标 | 数值 |
|---|---:|
| 抓起 | 19/28 |
| 抓起且指定部位命中 | 15/28 |
| timeout | 8/28 |
| 实际试提后失败 | 1/28 |
| 只因剩余试提预算不足而未触发 | 0/28 |

八次超时为 `B_9832、C_9816、C_9817、B_9836、B_9837、C_9813、C_9814、C_9818`。它们在整个控制序列里，`min(左指垫力, 右指垫力)` 的最大值均为 **0 N**。在 600 Hz 物理日志中也没有双指垫同时接触目标的记录。其中六场两指垫读数始终为 0；另两场只有单侧接触。因此不是“实际有 4.9 N，差一点到 5 N”这一类门槛问题。此结论限定于当前接触传感器的读数及其内侧指垫定义，未将视觉外观当成接触真值。

`C_9815` 在两侧约 22.3/19.7 N、夹紧余量 6.29 mm 时触发，实际执行 27 个试提/悬停控制步，但早期失去夹持，目标未有效离桌。不能把它解释为 2 mm 新余量阈值单独造成的失败，也不是“已稳定抬高 8 cm 后才掉落”。

### 时间和成功判定的实际含义

- 15 秒包含 16 步抬升、11 步悬停，所以完整试提最晚必须在第 **273 步，即 13.65 秒**启动。这是既定总预算的结果，不是渲染或检测器慢导致少给仿真步。当前两版 28 场都没有仅被这个边界拦下的回合。
- 碰撞、物体碰偏和 `Part Hit` 是独立诊断。统一判分不会仅因接近阶段有碰撞而直接判抓起失败；抓起错误部位仍会记 `success`，但“抓起且命中”为失败。
- 判分还要求手腕约 8 cm、物体至少上升 2 cm且悬停时无支撑、悬停至少 0.5 秒、相对滑动不超过 10 mm/15°。这些应在报告中明示，不能只口头描述成“离桌就算”。本轮唯一实际试提失败没有出现“仅因 10 mm/15° 稳定性门槛而失败”的情况。
- 指垫力目前取每个 20 Hz 控制步最后一个 600 Hz 物理样本。它理论上可能受接触求解波动影响；当前八次超时没有双指目标接触，不能把它们归因于抽样恰好漏掉稳定接触。建议先补每步力分布诊断，再决定是否用短窗统计，不直接降低阈值。

参考：[统一执行器](../../simulation/isaac_snapshot/unified_grasp.py)、[物理判分](../../simulation/isaac_snapshot/strict_grasp.py)、[传感与下发](../../simulation/isaac_snapshot/rigid_grasp_probe.py)。

**两个需要如实披露的数据限制：**

1. 已入库这 968 条的记录元信息均为旧夹爪/固定障碍；第 23 批已按动态障碍和 `adaptive` 运行，但审查快照时尚未完成整批入库。后续数据将混合两种生成版本，应分别统计。不能说“所有既有障碍数据已经解锁”。冻结开发/终榜场景仍是固定障碍；要测可推动障碍，应另立版本，不能暗中改动冻结基准。
2. 旧白盒/罐数据有 491 个监督步的目标略超出在线 `qpos±0.035 rad` 限幅，其中训练 291 步、验证 200 步，涉及 16 条轨迹；**再次裁剪的最大差仅约 0.0209°**。另有 22 个旧训练控制步使用了步内变化的原生指令，标签只存末尾目标。新增 508 条在这两项上均为 0。它们是小的执行一致性偏差，宜随重录规范统一，但不应夸大为当前大角度闭环跑偏的主因，也不应因此删除全部旧数据。

本轮未发现需要改模型结构、重写采样器或放松闭爪监督掩码的证据。检查点续跑中的随机种子、全局窗口顺序及加权分母在代码层面一致；合成梯度检查不是两卡 NCCL 的完整端到端训练测试。

## 5. 重复评测与解释边界

同种子并不保证 RTX 每个像素完全相同。此前 `C_9818` 两次复位的目标位姿相同，但首帧三视角平均像素差约 1.91 / 1.10 / 2.63（0–255），首条关节目标平均差约 0.064°。本轮核对了该留存诊断。因此一两场终态反转不能全部归因于某个门槛；收益应在相同执行器下成对验证，关键翻转场景可重复运行。

另一个解释问题是 Temporal Ensembling：当前 ACT 实现按旧预测块到新预测块排列，并使用 `exp(-m*i)`。**增大 m 会提高旧块权重，并不代表更快跟随新观测。** 本轮只补充代码注释，未更改已经定型的 `m=0.01`。
